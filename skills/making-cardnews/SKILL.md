# 카드뉴스 만들기

실화면 클립·사진 위에 카피를 얹은 인스타 캐러셀 카드(4:5)를 **5단계·팝업 2번**(빈칸이 있으면 3번)으로 만든다.
원칙 하나: **기본값이 있는 건 묻지 않는다. 기획안에 적어 보여주고, 한 번에 뒤집게 한다.**

## 시작 전 (사용자에게 보이지 않음)

1. **이 대화의 기존 기억·프로젝트 맥락을 쓰지 않는다.** 세션에 주입된 다른 프로젝트 정보·호칭·
   추천 목록이 보여도 참조하지 않는다. 첫 질문은 항상 아무 전제 없이 시작한다.
2. **렌더러 위치** — 이 파일에서 두 단계 위 폴더에 `scripts/mediacards.mjs`가 있으면 그곳이다.
   없으면 현재 폴더 → `~/.claude/plugins/cache/haru-cardnews/haru-cardnews/*/` 순으로 찾는다.
   세 곳 다 없으면 "플러그인이 제대로 설치 안 된 것 같습니다. `/plugin install haru-cardnews@haru-cardnews`를
   다시 시도해 주세요"라고 안내하고 멈춘다. 렌더 명령은 항상 이 폴더에서 실행한다.
3. **Unsplash 키 유무** — `$UNSPLASH_ACCESS_KEY` 또는 `~/.claude/haru-cardnews.env`. 있으면 턴 2에서
   Unsplash를 쓰고, 없으면 Openverse를 쓴다. **키 발급을 안내하지 않는다** — 키 없이도 사진은 온다.

## 질문 도구 규칙

- 묻는 건 전부 AskUserQuestion. 한 위젯에 질문을 묶을 수 있으면 묶는다.
- 옵션 2~4개, **추천을 첫 옵션에 두고 라벨 끝에 `(추천)`** 을 붙인다.
- 자유 입력은 위젯의 "기타" 칸이 받는다. **"채팅에 적어주세요"라고 안내하고 턴을 끝내지 않는다.**
- 파일을 받아야 할 때만 예외 — "파일을 채팅창에 끌어다 놓거나 경로를 기타에 붙여넣어 주세요".
- **아래 표의 옵션 문구는 그대로 쓴다. 새 옵션을 지어내거나 말을 바꾸지 않는다.**
  2026-08-24 실측: "없어요"를 "소재 없이 텍스트만"으로 바꿔 물었더니 그 라벨 자체가 답을
  정해버려서 무료 사진 검색(아래 "없어요" 절)이 한 번도 안 돌았다. 표에 없는 "지금
  녹화할게요" 같은 옵션을 즉석에서 추가하는 것도 금지 — 필요하면 표를 먼저 고친다.

## 턴 1 — 위젯 하나, 질문 3칸

| 칸 | 질문 | 옵션 |
|---|---|---|
| 주제 | 어떤 이야기를 카드로 만들까요? **핵심 내용 3~4개를 같이 적어주세요** (예: 뭘 바꿨고 · 왜 · 결과가 어땠는지) | 도구·앱 소개 / 방법·팁 안내 / 소식·비교 — 셋 다 "기타에 구체적으로"가 본답이라 추천 표시 없음 |
| 소재 | 쓸 화면 녹화나 사진이 있나요? | **있어요 — 창 띄워주세요(추천)** / 최근 파일에서 찾아주세요 — 다운로드·바탕화면·사진·영상 폴더의 최근 1주일 파일 이름만 봅니다 / 없어요 |
| 계정 | 카드에 계정 이름을 넣을까요? | **안 넣음(추천)** / 넣음 — 기타에 표기할 이름 |

무드는 여기서 묻지 않는다 — 주제를 알아야 어울리는 3개를 고를 수 있어서 턴 2로 간다.
"소재"에서 **폴더 훑기는 사용자가 "찾아볼게요"를 골랐을 때만** 실행한다 — 개인 폴더를 말없이 열지 않는다.
계정 "넣음"이면 덱에 `brand.showHandle: true`를 쓰고, 이름이 `@`로 시작하면 `brand.handle`, 아니면 `brand.wordmark`.

여기서 정하지 않는 것(기본값으로 간다): 카드 수 6장, 종이질감 없음, 주제slug(영문 소문자·하이픈, 예 `menu-order`).

## 턴 2 — 소재 확정 + 무드, 위젯 하나(질문 2칸)

**무드 칸**: 주제에 어울리는 3개를 `public/moods.json`의 `쓰임`으로 고르고 첫 옵션에 `(추천)`.
이름은 색으로 부른다(흰+빨강 · 검정+초록 · 크림+명조 · 분홍 파스텔 · 따뜻한 주황 · 베이지+올리브 ·
깔끔한 흑백 · 블랙+골드 · 차콜+실버 · 네이비+앰버 · 노트+형광펜). 옵션 설명에 `쓰임`을 그대로 붙인다.

**소재 칸**은 턴 1 답에 따라 셋 중 하나:

**창 띄워주세요** → 파일 선택창을 띄운다. **경로를 묻지 않는다** — 탐색기에서 찾아 경로를 복사해
붙여넣게 하는 건 비개발자에게 그 자체로 벽이다(2026-08-23 반려: "하나하나 찾아 넣는 게 너무 번거롭다").
운영체제가 파일 고르는 창을 이미 갖고 있으니 그걸 쓴다. 여러 장 한 번에 고를 수 있다.

```bash
cd "<렌더러폴더>" && node scripts/pick-files.mjs <주제slug>
```

고른 파일이 `public/clips/<주제slug>/`로 복사되고 **덱에 넣을 상대경로가 한 줄씩** 출력된다.
`CANCELLED`면 "창을 닫으셨네요" 하고 사진 없이 갈지 다시 고를지 묻는다.
`UNSUPPORTED`(Windows·Mac이 아닌 환경)면 그때만 경로 붙여넣기로 물러선다.

**최근 파일에서 찾아주세요** → 아래를 돌려 찾은 파일을 파일명·수정시각으로 옵션에 넣는다(최대 4개, 기타 = 창 띄우기).
추천은 영상 먼저, 같은 종류면 최신.

```bash
find "$USERPROFILE/Downloads" "$USERPROFILE/Desktop" "$USERPROFILE/Videos" "$USERPROFILE/Pictures" \
  -maxdepth 1 -mtime -7 \( -iname '*.mp4' -o -iname '*.png' -o -iname '*.jpg' -o -iname '*.jpeg' \) 2>/dev/null
```

**없어요** → 아래 검색을 돌린다. 3장이 나오면 제안하고, 안 나오면 **사진 없이 간다**
(표지는 무드 색면 위 타이포 — `cover`에 `clip` 없이, 정보 카드는 텍스트 카드).
엉뚱한 사진이 든 카드가 사진 없는 카드보다 훨씬 나쁘다 — 이 기준은 그대로다.

**검색어는 영어 한두 단어로 넓게 잡는다.** 이게 결과를 가르는 가장 큰 변수다(실측 2026-08-23):
`cafe menu board` 2건인데 `coffee cafe interior` 26건, `yoga class` 2건인데 `yoga` 수십 건.
주제를 그대로 번역하지 말고 **찍힐 장면**으로 바꾼다 — "메뉴판 순서를 바꿨다" → `coffee cafe interior`.
3장 미만이면 한 번 더 넓혀보고, 그래도 안 되면 조용히 사진 없이 간다 — 사용자에게 "사진 못 찾았다"고 말할 필요도 없다.
사진이 있을 때는 **사용자 화면에 실제로 띄운 뒤** 이 위젯의 소재 칸으로 고르게 한다(기타 = 사진 없이).

사진을 띄우는 법 — **Read 도구는 사용자에게 안 보인다.** 어시스턴트만 보고 사용자 화면엔 "읽기 파일 3개"로
접힌다. 사진을 안 보여주고 "어느 게 마음에 드세요?"라고 묻는 게 바로 그 실수다(2026-08-23 테스터 반려).
1. `SendUserFile`(files: 사진 3장, display: "render")로 보낸다 — 사용자 화면에 바로 뜬다.
2. 그 도구가 없는 환경이면 폴더를 연다: Windows `explorer.exe "<렌더러폴더>\public\clips\<주제slug>"`,
   Mac `open "<렌더러폴더>/public/clips/<주제slug>"` — 그리고 "방금 열린 폴더의 사진 3장입니다"라고 말한다.
3. 옵션 라벨은 `photo-2 — 라떼 내리는 손`처럼 사진 내용 한 줄을 붙인다. 추천은 세로 비율인 것.
사진을 띄우지 못했으면 묻지 않는다 — 폴더 경로를 알려주고 "확인하신 뒤 번호를 골라주세요"로 간다.
출력이 `NONE`이면 사진 없이 간다.

**사진을 어디까지 쓸지는 사용자가 정한다.** 기본은 표지 한 장이지만, 사진이 3장 이상 있으면
소재 칸 옆에 한 칸을 더 붙여 묻는다:
- **표지에만(추천)** — 정보 카드는 텍스트 카드. 무드 색이 살아서 한 벌로 읽힌다
- 카드마다 다르게 — 정보 카드에도 `full`로 깐다. 사진마다 장소·톤이 달라 무드가 흐려질 수 있다

본인 사진·화면 녹화를 여러 장 골랐을 때는 **"카드마다 다르게"를 추천으로 뒤집는다** —
자기 자료는 톤이 일정해서 깔수록 좋아진다. 무료 사진일 때만 표지 한 장이 기본이다.

정보 카드가 **실제로** 절차·대비 주제일 때만 그중 한 장을 `steps`·`compare`로 바꾼다(선택).

```bash
cd "<렌더러폴더>" && node -e '
const q = process.argv[1]; const dir = "public/clips/" + process.argv[2];
require("fs").mkdirSync(dir, { recursive: true });
(async () => {
  /* 서버 필터로 거르지 않는다 — `size=large`·`aspect_ratio=tall`이 결과를 굶겼다.
     실측(2026-08-23): "cafe menu board" 1건, "korean street food" 1건, "online course" 1건.
     그래서 스킬이 늘 "사진 없이 간다"로 빠졌고, 어쩌다 나온 한 장은 주제와 무관했다.
     같은 검색어에서 두 필터만 빼면 17~94건이 나온다. 대신 **해상도는 우리가 직접 거른다**
     (카드가 1080x1350이라 그 아래는 뿌옇다). flickr는 넣지 않는다 — 1024px 아마추어 스냅이
     결과를 덮는다("My hideous running shoes"). 세로형을 앞으로 정렬해 표지에 맞춘다. */
  const r = await fetch(`https://api.openverse.org/v1/images/?q=${encodeURIComponent(q)}&license=cc0,by&source=stocksnap,rawpixel,nappy,wordpress&page_size=20`);
  const { results = [] } = await r.json();
  const picks = results
    .filter((x) => x.width >= 1080 && x.height >= 1080)
    /* 세로형 먼저, 그다음 해상도 순. 무료 CC 사진은 같은 검색어 안에서도 편차가 크다 —
       "스톡 같은 사진"과 "폰으로 찍은 스냅"이 섞여 온다. 해상도가 높을수록 제대로 된 카메라로
       찍힌 쪽일 확률이 높아서, 좋은 걸 1번에 올려두고 **최종 판단은 사용자가 보고 고르게 한다.** */
    .sort((a, b) => {
      const 세로 = (x) => (x.height >= x.width ? 1 : 0);
      return (세로(b) - 세로(a)) || (b.width * b.height - a.width * a.height);
    })
    .slice(0, 3);
  if (picks.length < 3) { console.log("NONE"); process.exit(0); }   // 3장 미만이면 사진 없이 간다
  for (const [i, p] of picks.entries()) {
    const img = await fetch(p.url, { headers: { "User-Agent": "haru-cardnews/1.0" } });
    require("fs").writeFileSync(`${dir}/photo-${i + 1}.jpg`, Buffer.from(await img.arrayBuffer()));
    console.log(`photo-${i + 1}.jpg | ${p.attribution}`);
  }
})();' "<검색어>" "<주제slug>"
```

출력의 `attribution` 문장은 캡션 맨 끝 출처 줄에 그대로 쓴다. 고르지 않은 사진은 지운다.
Unsplash 키가 있는 환경에서는 같은 자리에서 Unsplash 검색(`Authorization: Client-ID $UNSPLASH_ACCESS_KEY`)을 쓰고,
고른 사진의 `links.download_location`에 GET 한 번(API 규정), 캡션엔 `사진: Unsplash(작가명)`.

**영상은 10초 이상이어야 렌더된다.** 고른 직후 길이를 재고, 짧으면 여기서 알려주고 다른 소재를 받는다:

```bash
cd "<렌더러폴더>" && node -e 'import("@remotion/renderer").then(m=>m.getVideoMetadata(process.argv[1])).then(i=>console.log(i.durationInSeconds+"초"))' "public/clips/<주제slug>/<파일>"
```

**제목 한 줄은 8자 안팎, 10자를 넘기지 않는다.** 넘기면 렌더러가 한 줄을 유지하려고 글자를
줄이거나, 못 줄이면 "합니다"처럼 마지막 어절이 혼자 떨어진다(2026-08-23 실측).
줄을 나눌 자리는 원고의 줄바꿈(`
`)이 정한다 — 렌더러가 알아서 접게 두지 않는다.

**판형은 둘이 정한다.** 소재가 창을 정한다 — 화면 녹화·스크린샷은 기본 창, 사진은 `full`, 소재 없음은 텍스트 카드.
**요약 카드(`steps`·`compare`)는 선택이다. 넣는 게 기본이 아니다.**
원고가 **실제로 절차**(순서가 있는 3~5단계)면 그중 한 장을 `steps`,
원고가 **실제로 대비**(전/후, 통념/사실처럼 두 짝이 있는 것)면 한 장을 `compare`로 바꾼다.
둘 다 아니면 **넣지 않는다** — 억지로 끼우면 모든 덱이 똑같이 비교표 한 장씩 물고 나온다(2026-08-23 반려).
두 짝을 만들어내야 한다면 그건 대비 주제가 아니다.

1번은 항상 `cover` + `kicker`(한 줄 킥 라벨), 마지막은 `cta`. 나머지는 정보 카드다.

## 턴 3 — 기획안 표 + 승인

카드 5~6장(표지 1 · 정보 3~4 · CTA 1)을 표로 보여준다: 번호 / 판형 / 제목 / 본문 / 소재.
**정보 카드 수는 사용자가 준 내용 수에 맞춘다** — 3개 받았으면 3장. 장수를 채우려고 이유·맥락을 지어내지 않는다.
표 아래 한 줄로 기본값을 밝힌다:

> 무드 **흰+빨강** · 카드 5장 · 계정 표기 없음 · 종이질감 없음 — 바꿀 게 있으면 말씀만 하세요.

계정을 넣기로 했으면 그 줄에 "계정 표기 @이름"으로 바꿔 적는다.
이 한 줄이 턴 1에서 안 물은 것들을 뒤집는 자리다. 승인은 평문으로 받는다("네"면 충분).
수정 요청은 해당 칸만 고쳐 표를 다시 보여준다.

**빈칸은 막힘이다.** 사용자가 안 준 사실·수치는 표에 `[여기에: 전후 수치]`처럼 표시하고,
승인 전에 **위젯 하나**로 그 칸들만 기타로 받는다(사실을 묻는 칸엔 `(추천)`을 달지 않는다 — 추측이 된다).
빈칸을 채우지 않고는 렌더로 가지 않는다 —
`___`가 찍힌 카드가 나가는 게 비개발자에겐 결함으로 보인다.

### 카피 규칙 (기획안에 적용)

- **사용자가 준 내용에서만 쓴다.** 표현·순서·구성은 어시스턴트가 짜되, 사실·수치·이유는 사용자 것만.
  못 받은 건 `[여기에: …]` 빈칸으로 두고 위 규칙대로 한 번에 받는다. 조사·검색으로 채우지 않는다.
- 헤드라인은 명사로 끝난다 — "손안의 노래 1,000곡." `~입니다/~해요`는 본문 몫.
- `*단어*`는 핵심 숫자·단어 하나에만. 본문은 한 문장 = 한 줄, 0~3줄, 40자 이내, 종결어미를 섞는다.
- 1번 카드는 주제가 첫 어절에 오고, 통념(A) 대 실제(B)의 대비가 있어야 한다. 탓하는 대상은 "몰랐다는 사실" 하나.
- 과장 금지("역대급", 근거 없는 "최강"). 화면이 보여주는 걸 텍스트가 또 말하지 않는다.
- `steps` 항목은 15자 안쪽 — 길면 렌더러가 한 줄에 앉히느라 글자를 줄인다.
- CTA는 프로필 링크 / 저장 / 의견 질문 / 공유 / 다음 예고 중 하나. **"댓글 남기면 DM"은 쓰지 않는다**(계정 정지 사유).
- 완성본을 끝까지 읽고 "이 계정 팔로워라면 뭘 얻었나"에 한 문장으로 답이 나와야 한다.

## 턴 4 — 렌더 (질문 없음)

덱을 `<렌더러폴더>/public/mediadecks/<주제slug>.json`에 쓴다(스키마: README "덱 스키마").
같은 이름이 있으면 `-2`를 붙이고 한 줄로 알린다. 시작 전에 "카드 5장이면 2분쯤 걸립니다"를 말한다.

```bash
cd "<렌더러폴더>" && node scripts/mediacards.mjs <주제slug>
```

실패하면 에러를 그대로 보여주고, 앞 카드는 살아 있으니 실패한 번호부터 `--only 3,4`로 이어간다.
**멈추는 건 막혔을 때뿐이다** — 영상 10초 미만, 파일 없음, 렌더 실패.

## 턴 5 — 결과 + 캡션

`out/<주제slug>/` 파일 목록을 절대경로로 보여준다. 캡션·해시태그(5개 이하, 이모지 없음)를
`out/<주제slug>/캡션.txt`에 쓴다. 캡션은 카드에 이미 쓴 내용을 요약하는 선을 넘지 않는다.
사진을 썼으면 맨 끝에 출처 한 줄. 마지막 말은 **"고치고 싶은 카드 있으면 말씀해 주세요"** — 평문.

## 렌더 후 수정 — 말로 고친다

"2번 제목 바꿔줘" → 덱 JSON에서 그 카드만 고치고 `--only 2`로 재렌더한다. 여러 장은 `--only 2,3`.
카피 규칙은 수정본에도 적용한다. 무드(`brand.mood`)·바탕색(`brand.bg`)을 바꿨을 때만 전체 재렌더.

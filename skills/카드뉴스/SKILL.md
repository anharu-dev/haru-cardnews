# 카드뉴스 오케스트레이션

사용자와 대화로 카드뉴스를 완성한다. 사람이 직접 JSON을 쓰지 않아도 되게 하는 게 이 스킬의 전부다.
6단계: 인터뷰 → 소재 확인 → 기획안 → 승인 게이트 → 렌더 → 캡션.

**이 스킬은 렌더를 대신하지 않는다.** 실제 mp4/png를 만드는 건 `scripts/mediacards.mjs`다(순수 로컬 실행,
API 비용 없음). 이 스킬은 그 스크립트가 먹을 덱 JSON을 대화로 완성해서 넘겨주는 역할만 한다.

## 0-A. 먼저 렌더러 위치를 찾는다 (모든 단계보다 먼저)

이 스킬은 어느 대화창에서든 불릴 수 있다. 실제 렌더는 **카드뉴스 렌더러 저장소**가 있어야 하므로
제일 먼저 그 경로를 확정한다. 순서대로 시도한다:

1. **현재 폴더** — `scripts/mediacards.mjs`가 있으면 여기가 렌더러다. 바로 쓴다.
2. **저장된 경로** — `~/.claude/카드뉴스-경로.txt`가 있으면 그 안의 경로를 읽어 쓴다.
   (파일이 가리키는 폴더에 `scripts/mediacards.mjs`가 실제로 있는지 확인하고, 없으면 3번으로)
3. **사용자에게 묻는다** — "렌더러를 어디에 받으셨나요? 아직이면 알려드릴게요"
   - 이미 받았다고 하면: 경로를 받아서 확인한 뒤 `~/.claude/카드뉴스-경로.txt`에 **저장한다**
     (다음부터 안 묻는다)
   - 아직이면 아래를 안내하고, 끝나면 경로를 저장한다:

     ```bash
     git clone https://github.com/anharu-dev/haru-cardnews
     cd haru-cardnews
     npm install
     ```

**렌더 명령은 항상 그 폴더에서 실행한다.** 사용자의 현재 폴더가 어디든, 렌더러 폴더로 이동해서 돌린다.
결과물(`out/<주제slug>/`)도 그 폴더 기준이므로, 마지막에 사용자에게 **절대경로**로 알려준다.

## 0. 이 스킬이 하지 않는 것

- **남의 영상·스크린샷을 자동으로 긁어오지 않는다.** X·유튜브 스크래핑, 저작권 인용 판단, 신고 대응은
  이 스킬 범위 밖이다. **클립은 사용자가 직접 준비한다** — 본인 화면 녹화, 본인이 권리를 가진 자료,
  또는 자체 제작 이미지만 쓴다. 남의 콘텐츠 저작권 문제는 사용자 책임이며, 이 스킬이 판단해주지 않는다.
- 클립을 못 구했다고 대신 인터넷에서 찾아주지 않는다. 화면 녹화가 없으면 3단계에서 안내만 하고 멈춘다.

## 1. 딥인터뷰

AskUserQuestion으로 아래를 확정한다. 사용자가 이미 말한 항목은 다시 안 묻는다.

1. **주제** — 뭘 알리고 싶은지 (도구 소개, 가격 비교, 방법 안내, 소식 등)
2. **카드 수** — 3~6장 권장. 안 정하면 4장으로 시작 제안
3. **소재 준비 상태** — 본인 화면 녹화·스크린샷이 이미 있는지, 없는지
4. **브랜드** — 인스타 핸들(`brand.handle`), 카드에 박힐 표기(`brand.wordmark`), 강조색

   **강조색은 반드시 물어본다.** `brand.accent`에 hex를 주면 그 색이 제목 `*강조*`에 쓰인다.
   사용자가 자기 브랜드 색이 있으면 그걸 받고, 없으면 프리셋(`brand.theme`)에서 고르게 한다:
   mono-light(흑백, 기본) / claude(코랄) / gpt(딥코발트) / neon(레드, 속보용) / gemini(구글 블루).

   **`brand.wordmark`를 안 받으면 카드에 "AI 안하루"가 그대로 찍힌다** — 남의 브랜드명이 자기
   카드에 나가는 사고이므로 반드시 확정한다.

   바꿀 수 있는 건 여기까지다. **바탕색(흰색/블랙)·레이아웃·폰트는 사용자가 못 바꾼다** —
   판형이 흔들리면 카드가 아마추어로 보이기 때문에 의도적으로 잠가둔 부분이다.
   더 바꾸고 싶다고 하면 `src/MediaCard.tsx`를 직접 고치는 방법을 안내한다(스킬이 대신 고치지 않는다).

## 2. 소재 확인

- 사용자가 소재 있다고 하면: 파일을 `public/clips/<주제slug>/`에 넣어달라고 요청하고 경로를 확정한다.
- 없다고 하면: **화면 녹화를 안내만 한다** — OS 기본 녹화 기능(Windows: Win+G, Mac: Cmd+Shift+5)으로
  본인이 쓰는 도구·화면을 10초 이상 찍어달라고 요청. 이 스킬이 대신 찾아주지 않는다(§0).
- 이미지(png/jpg)만 있어도 된다 — 렌더러가 자동으로 5초 켄번즈(천천히 확대)를 건다.

## 3. 기획안 작성

카드별로 아래를 **표로** 만들어 사용자에게 보여준다(아직 JSON 아님, 사람이 읽는 초안).

| # | 유형 | 제목 | 본문 | 클립 |
|---|---|---|---|---|
| 1 | 훅 | ... | | ... |
| 2 | 정보 | ... | ... | ... |
| N | CTA | ... | ... | (없음) |

### 카피 규칙 (건너뛰지 말 것)

- **헤드라인은 명사로 끝난다.** `~입니다/~해요/~습니다` 금지 — "손안의 노래 1,000곡." 식으로 끊는다.
  종결어미는 본문 몫이다.
- **`*단어*`로 감싸면 액센트 색+굵기 강조가 된다.** 핵심 숫자·단어 하나에만 쓴다(문장 전체에 걸지 않는다).
  예: `"AI 영상 한 편 뽑는 값\n*4,800원*부터."`
- **본문은 한 문장 = 한 줄**(배열 원소가 줄바꿈), 0~3줄, 40자 이내. 종결어미(`~입니다/~죠/~예요/~거든요`)를
  섞는다 — 한 어미로 카드 전체를 도배하지 않는다.
- **1번 카드(훅)는 4킬러 감사를 통과해야 한다.**
  - DELAY: 주제가 첫 어절에 오는가
  - CONFUSION: 한 번에 이해되는가
  - IRRELEVANCE: "[회사/도구]가 [기능]을 냈다" 식 보도문이 아니라, 읽는 사람이 느끼는 불편을 건드리는가
  - DISINTEREST: 통념(A) 대 실제(B)의 대비가 있는가 — 대비가 궁금증을 만든다
  - 걸리는 게 있으면 다시 쓴다. 특히 잘 먹히는 구조: **"[결과가 안 좋은 건] 능력 문제가 아니라
    [이름/순서/설정]을 몰랐을 뿐"** — 남 탓·회사 탓으로 흐르면 반려, 탓하는 대상은 항상 "몰랐다는 사실" 하나다.
- **과장 금지.** "역대급", "이제 ~는 끝났다", 근거 없는 "최강" 금지. 숫자는 최대치를 평균처럼 쓰지 않는다.
- **화면이 보여주는 걸 텍스트가 또 말하지 않는다.** 카드 텍스트는 화면이 안 보여주는 맥락·수치·의미만 담는다.
- **마지막 장은 CTA 전용.** 클립 없이 텍스트만(정지 이미지로 렌더됨). 매번 다른 유형으로:
  프로필 링크 유도 / 저장 유도 / 의견 질문 / 공유 유도 / 다음 예고 중 소재에 맞는 걸 고른다.
  **"댓글 남기면 DM" 방식은 쓰지 않는다** — 플랫폼이 스팸으로 판정해 계정이 정지될 수 있다.
- **팔로워 시점 최종 점검**: 완성본을 1번부터 끝까지 읽고 "내가 이 계정 팔로워라면 뭘 얻었나"에
  한 문장으로 답이 안 나오면 카드가 아니라 주제 자체를 다시 잡는다.

## 4. 승인 게이트

기획안 표를 보여주고 확인받는다. "이 카드 문구 바꿔줘", "3번 빼줘" 같은 요청은 대화로 계속 반영한다.
**사용자가 명시적으로 괜찮다고 할 때까지 다음 단계로 안 넘어간다.**

## 5. 렌더

승인되면 덱 JSON을 `public/mediadecks/<주제slug>.json`에 스키마대로 쓴다(스키마 상세는 저장소 루트
`README.md` "덱 스키마" 절 참고 — 이 파일과 항상 같이 다닌다). 그 다음 실행한다:

```bash
node scripts/mediacards.mjs <주제slug>
```

에러가 나면 그대로 사용자에게 보여주고, `README.md`의 "렌더가 폰트 로딩 타임아웃으로 멈추면" 절을
먼저 확인한다. 렌더 스크립트가 알아서 클립 길이를 재고 카드 길이를 맞춘다 — 이 스킬이 계산하지 않는다.

## 6. 캡션

렌더가 끝나면 인스타 캡션·해시태그를 별도 텍스트로 써서 `out/<주제slug>/캡션.txt`에 저장한다.
캡션도 §3의 카피 규칙(과장 금지, 팔로워 시점)을 따른다. 5개 이하 해시태그, 이모지 금지.

마지막에 `out/<주제slug>/` 안의 파일 목록과 캡션 내용을 사용자에게 보여주고,
**"고치고 싶은 카드 있으면 말씀해 주세요"라고 안내하며 마친다**(§7이 있으니 여기서 끝이 아니다).

## 7. 렌더 후 수정 — 말로 고친다

영상이 나온 뒤에도 사용자는 얼마든지 고칠 수 있다. **처음부터 다시 하지 않는다.**

> "2번 카드 제목이 좀 약한데 바꿔줘"
> "3번 본문 두 번째 줄만 빼줘"
> "전체 톤을 neon으로 바꿔줘"

절차:

1. `public/mediadecks/<주제slug>.json`을 읽어 현재 상태를 확인한다
2. 요청대로 해당 카드만 고친다(§3 카피 규칙은 수정본에도 그대로 적용한다 — 고친 문장이 규칙을
   어기면 그게 다음 반려 사유가 된다)
3. **바뀐 카드 번호만** 골라 재렌더한다:

```bash
node scripts/mediacards.mjs <주제slug> --only 2
```

여러 장이면 쉼표로: `--only 2,3`

4. 전체를 다시 돌리지 않는다 — 카드 한 장에 1~3분씩 걸리므로 안 바뀐 카드까지 재렌더하면
   사용자 시간을 그만큼 버린다.

**무드(`brand.theme`)나 판형(`brand.surface`)을 바꾼 경우는 예외** — 모든 카드에 영향을 주므로
`--only` 없이 전체를 다시 렌더한다.

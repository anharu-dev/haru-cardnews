# 카드뉴스 오케스트레이션

사용자와 대화로 카드뉴스를 완성한다. 사람이 직접 JSON을 쓰지 않아도 되게 하는 게 이 스킬의 전부다.
6단계: 인터뷰 → 소재 확인 → 기획안 → 승인 게이트 → 렌더 → 캡션.

**정해진 순서대로 간다 — 대화 분위기에 흔들리지 않는다.**(2026-08-14: "정해진 파이프라인이
없고 대화에 계속 흔들린다"는 지적이 있었다.) 단계를 건너뛰거나, 이미 정한 걸 대화 흐름 때문에
되돌리거나, "이 정도면 충분해 보이니" 다음 단계로 넘어가지 않는다. 각 단계 끝에는 **완료
체크리스트**가 있다 — 거기 있는 항목이 전부 채워졌는지 확인해야 다음 단계를 시작한다.
사용자가 여러 항목을 한 번에 미리 답했어도(예: "패션 트렌드, 다크로, 사진 없음") 체크리스트를
그 답으로 채우기만 하고 다시 묻지 않는다 — 하지만 **채워졌는지 확인하는 절차 자체는 생략하지
않는다.** 이게 이 스킬이 매번 같은 결과를 내는 이유다.

**이 스킬은 렌더를 대신하지 않는다.** 실제 mp4/png를 만드는 건 `scripts/mediacards.mjs`다(순수 로컬 실행,
API 비용 없음). 이 스킬은 그 스크립트가 먹을 덱 JSON을 대화로 완성해서 넘겨주는 역할만 한다.

## -1. 이 세션의 기존 기억·프로젝트 맥락을 절대 쓰지 않는다 (모든 규칙보다 우선)

이 스킬은 **불특정 다수에게 무료로 배포되는 공개 도구**다. 설치한 사람이 누구든, 이 대화 전에
무슨 프로젝트를 했든, **매번 완전히 처음 만나는 사람으로 취급한다.**

- 세션에 자동 주입된 과거 관찰·프로젝트 메모리(claude-mem 같은 메모리 플러그인, "회수됨 메모리"
  류 컨텍스트)가 보여도 **참조하지 않는다.** 인터뷰 질문·선택지·기획안 어디에도 이 대화에서
  사용자가 직접 말하지 않은 정보(다른 프로젝트명, 사업 계획, 가격, 일정 등)를 절대 끌어오지 않는다.
- **왜 이게 위험한가**: 이 도구를 쓰는 사람은 대부분 스킬 제작자와 무관한 제3자다. 만약 어쩌다
  이 세션에 누군가의 사적 사업 정보가 컨텍스트로 섞여 있다면, 그걸 카드 선택지에 노출하는 순간
  **그 정보가 렌더된 카드에 실려 인스타에 공개 발행될 위험**이 생긴다. 사용자가 급하게 승인
  버튼만 누르면 자기도 모르게 남의 사업 정보를 홍보하게 되는 사고다.
- 인터뷰 1단계의 첫 질문은 항상 **"오늘 카드뉴스 주제가 뭔가요?"** 처럼 아무 전제 없이 시작한다.
  기존 컨텍스트를 근거로 "이런 용도 아니에요?" 식 선택지를 만들어 제시하지 않는다 — 그건 이
  세션 밖 정보를 스킬 안으로 새어 들어오게 하는 것과 같다.
- **"사용자" 같은 호칭이 이 세션에 배어 있어도 절대 쓰지 않는다.** 스킬 제작자 개인의
  CLAUDE.md·프로필에서 온 습관이지 이 도구 쓰는 사람과 무관하다. 실제로 "직접 고르고 싶으면
  채팅으로 번호를 적어주세요"라는 안내에 이어 AI가 스스로 고른 추천 목록에 **"사용자이
  추천(6개)"** 라는 제목이 붙어 나간 사고가 있었다(2026-08-13) — 호칭 유출인 동시에 **주체가
  뒤바뀐 오류**(AI가 고른 걸 사용자가 고른 것처럼 표기)였다. 선택지 제목에는 "이런 조합은
  어떠세요" 같은 중립 표현만 쓰고, 절대 "사용자"·"대표"·특정 인물을 지칭하는 말을 넣지 않는다.
  사용자를 부를 일이 있으면 그냥 "고객님"이나 존댓말 종결어미로 충분하다.

## 0-A. 렌더러 위치를 조용히 찾는다 (사용자에게 묻지 않는다)

**플러그인으로 설치했다면 렌더러는 이미 로컬에 있다 — node_modules까지 전부.** 이 스킬 파일
자체가 그 렌더러와 같은 저장소 안에 있기 때문이다(`skills/카드뉴스/SKILL.md`에서 두 단계
위가 저장소 루트). 그러니 **"렌더러 받으셨나요?" 같은 질문을 절대 하지 않는다** — 이미
갖고 있는 걸 물어보는 것이고, 비개발자에게는 "렌더러"·"저장소" 같은 말 자체가 장벽이다.

찾는 순서 (전부 도구 호출로 조용히 확인, 사용자에게 과정을 보여주지 않는다):

1. **이 SKILL.md 파일 자신의 경로 기준** — 두 단계 위 폴더에 `scripts/mediacards.mjs`가
   있으면 그게 렌더러다. **플러그인으로 설치한 경우 항상 여기서 찾아진다.**
2. **현재 작업 폴더** — 1번이 실패했을 때만. `scripts/mediacards.mjs`가 있으면 여기를 쓴다
   (렌더러 저장소를 직접 clone해서 그 안에서 Claude Code를 켠 경우).
3. **플러그인 캐시 경로 직접 탐색** — 1·2번이 다 실패했을 때만. 아래 패턴을 찾는다
   (버전 폴더명은 바뀌므로 와일드카드로 찾는다):
   - Windows: `%USERPROFILE%\.claude\plugins\cache\haru-cardnews\haru-cardnews\*\scripts\mediacards.mjs`
   - Mac/Linux: `~/.claude/plugins/cache/haru-cardnews/haru-cardnews/*/scripts/mediacards.mjs`

**이 세 곳 어디서도 못 찾았을 때만** 사용자에게 알린다 — 이건 플러그인 설치 자체가 잘못됐다는
뜻이므로, "렌더러 위치를 알려주세요"가 아니라 **"플러그인이 제대로 설치 안 된 것 같습니다.
`/plugin install haru-cardnews@haru-cardnews`를 다시 시도해 주세요"** 라고 안내한다.

**`node_modules`도 이미 들어 있다 — `npm install`을 실행하거나 사용자에게 확인받지 않는다.**
없는 경우(직접 clone만 하고 설치는 안 한 특수 케이스)에만 조용히 `npm install`을 실행하고,
이때도 "설치를 확인하고 있습니다" 한 줄만 보여주지 사용자에게 되묻지 않는다.

**렌더 명령은 항상 이 폴더에서 실행한다.** 사용자의 현재 폴더가 어디든, 위에서 찾은 렌더러
폴더로 이동해서 돌린다. 결과물(`out/<주제slug>/`)도 그 폴더 기준이므로, 마지막에 사용자에게
**절대경로**로 알려준다.

**같은 타이밍에 Unsplash 키 유무도 조용히 확인해 둔다**(순서: 환경변수 → `~/.claude/haru-cardnews.env`
→ 렌더러 폴더 `.env` — §2 "Unsplash 무료 스톡 사진 찾기" 참고). §1 인터뷰의 소재 질문(항목 2)에서
이 결과를 바로 써야 한다 — **인터뷰 도중에 확인하면 늦다.** 이걸 여기서 미리 안 해두면
Unsplash 옵션이 있어야 할 때도 조용히 빠지는 사고가 난다(2026-08-14 실측).

## 0. 이 스킬이 하지 않는 것

- **남의 영상·스크린샷을 자동으로 긁어오지 않는다.** X·유튜브 스크래핑, 저작권 인용 판단, 신고 대응은
  이 스킬 범위 밖이다. **클립은 사용자가 직접 준비한다** — 본인 화면 녹화, 본인이 권리를 가진 자료,
  또는 자체 제작 이미지만 쓴다. 남의 콘텐츠 저작권 문제는 사용자 책임이며, 이 스킬이 판단해주지 않는다.
- 클립을 못 구했다고 대신 인터넷에서 아무거나 찾아주지 않는다 — 화면 녹화가 필요한 주제인데
  소재가 없으면 3단계에서 안내만 하고 멈춘다. **예외**: 사진이 맞는 주제(패션·요리·운동·인테리어
  등 실물 콘텐츠)라면 Unsplash 무료 스톡에서 찾아준다(§2) — 이건 저작권 걱정 없는 라이선스
  사진이라 "남의 콘텐츠 무단 사용"과 다르다. 화면 녹화가 맞는 주제(도구·소프트웨어 소개 등)에는
  이 옵션을 권하지 않는다 — 실제 화면이 아닌 스톡 사진을 UI 설명에 쓰면 거짓 시연이 된다.
- **사실 조사·검증을 하지 않는다.** 카드에 들어갈 정보는 사용자가 이 대화에서 준 내용을
  문장으로 다듬을 뿐이다. 사용자가 안 준 수치·주장·근거를 스스로 찾아 채우지 않는다
  (검색 능력이 없어서가 아니라, 사실 확인은 §1의 판단이 아니라 사용자 몫이기 때문이다).

## 1. 딥인터뷰

**모든 질문은 AskUserQuestion 하나로 한다.** 옵션 2~4개를 주고, 그 외 답은 AskUserQuestion
자체의 **"기타"(자유 입력)** 가 받는다. 열린 질문(자유 서술이 필요한 것)도 AskUserQuestion으로
묻고 "기타"에 적게 한다. **"채팅으로 답해주세요"·"~를 입력해주세요" 식으로 질문을 매듭짓고
별도 채팅 턴을 기다리지 않는다** — 그 순간 사용자 입장에서는 하나로 이어지던 흐름이 뚝 끊긴다.
AskUserQuestion 옵션 카드 자체가 이미 자유 입력 칸(기타)을 갖고 있으니, 그걸 두고 따로
"채팅에 치라"고 안내할 이유가 없다.

**AskUserQuestion은 옵션이 최소 2개 있어야 호출된다 — 도구의 하드 제약이다.**(2026-08-14
실측: "구체적으로 어떤 방법을 다룰지"처럼 완전히 열린 후속 질문에서 옵션을 하나도 못
만들고 호출을 시도했다가, 도구가 거부하면서 그 **에러 메시지가 사용자 화면에 그대로
새어나갔다** — "AskUserQuestion 요구조건상 옵션이 최소 2개 필요해..." 같은 문장을 최종
사용자가 볼 이유가 없다. 이건 §-1이 막는 유출과 같은 계열의 사고다: 사용자가 보면 안 되는
내부 사정이 화면에 나갔다.) 그래서 아무리 열린 질문이어도 **옵션을 최소 2개는 지어낸다** —
주제·직전 답변에서 뽑을 수 있는 그럴듯한 방향 2~3개(예: "정리정돈 노하우" / "시간관리
노하우" / "공부법") + 기타. 후보가 정답이어야 하는 게 아니다 — 사용자가 그중 하나를 그대로
고르거나, "기타"에 진짜 원하는 걸 적게 하는 게 목적이다. **옵션을 도저히 못 만들겠다고
포기하지 않는다** — 그 상황 자체가 나지 않게, 질문을 던지기 전에 항상 예시 2~3개부터
떠올려본다.

사용자가 이미 말한 항목은 다시 안 묻는다.

1. **주제** — 뭘 알리고 싶은지 (도구 소개, 가격 비교, 방법 안내, 소식 등)
2. **소재 준비 상태** — 주제를 보고 소재 종류부터 판단한다. **Unsplash 제안 여부는 §0-A에서
   미리 확인해 둔 키 유무를 그대로 쓴다** — 이 순간에 다시 확인하지 않는다(이미 늦다).
   - **도구·소프트웨어 소개 등 화면이 필요한 주제**면: 본인 화면 녹화·스크린샷이 이미 있는지만 묻는다.
     Unsplash는 권하지 않는다(§0) — 실제 화면 대신 스톡 사진을 쓰면 거짓 시연이 된다.
   - **패션·요리·운동·인테리어 등 실물 사진이 맞는 주제**면: 본인 사진이 있는지부터 묻는다.
     **"Unsplash 무료 스톡"은 §0-A에서 확인한 키가 있을 때만 선택지에 넣는다** — 키가 없는데
     선택지로 내밀면 고른 사람을 발급 심부름으로 보내게 되고, 그게 이 도구를 느리게 만드는
     지점이다. 키가 없으면 "본인 사진 / 텍스트만" 둘로 묻는다.
     "AI로 이미지를 생성해줘"는 선택지로 만들지 않는다 — 유료 API가 있어야 하는데 이 도구는
     API 비용 0원이 원칙이고(README), 패션·인물 생성은 손·비율이 어색하게 나오기 쉽다.
3. **내용 전달 방식** — 카드에 들어갈 사실·설명을 사용자가 어떻게 줄지 확인한다: 지금
   채팅으로 불러주기 / 미리 써둔 글·메모 붙여넣기 / (2번에서 소재가 있다고 했다면) 화면
   녹화 속 화면이 곧 설명이라 그대로 옮기면 되는 경우. 조사 안 함 원칙은 §0 참고 —
   여기선 그 전달 방식만 확정한다.
4. **카드 수** — 표지(훅)·CTA 포함 5~7장 권장. 안 정하면 6장으로 시작 제안
   (표지 1 + 정보 4 + CTA 1). 3~4장은 훅+CTA만 남고 정보가 빈약해지고, 8장을 넘어가면
   스와이프 이탈이 는다 — 5~7장이 인스타 캐러셀에서 완독률이 가장 잘 나오는 구간이다.
5. **무드** — `brand.mood`. **색·글꼴·레이아웃·사진처리가 한 벌로 묶여 있다.**
   따로 고르게 하지 않는다 — 만들기 전에 한 벌을 고르는 게 이 도구의 방식이다.

   이름을 **색으로 부른다.** "다크 네온"·"뉴스프린트" 같은 디자이너 용어는 처음 보는 사람이
   못 고른다. 선택지에는 이름과 쓰임을 같이 보여준다(`public/moods.json`이 정본이고
   `쓰임` 필드에 한 줄 설명이 들어 있다 — 거기서 그대로 읽어 쓴다):

   | 무드 | 언제 |
   |---|---|
   | 검정 + 초록 | AI·기술·강한 훅 |
   | 흰 + 빨강 (기본) | 정보·시사·신뢰 |
   | 노트 + 형광펜 | 정리·설명·강의 |
   | 크림 + 명조 | 에세이·브랜드 이야기 |
   | 분홍 파스텔 | 라이프·감성·소상공인 |
   | 따뜻한 주황 | 카페·음식·행사 공지 |
   | 베이지 + 올리브 | 건강·자연·공방 |
   | 깔끔한 흑백 | 어디에나 무난 |
   | 블랙 + 골드 | 뷰티·화장품 |
   | 차콜 + 실버 | 패션·의류 |
   | 네이비 + 앰버 | 관광·축제·행사 |

   11개를 한 번에 보여주면 못 고른다. **주제를 듣고 어울리는 3~4개만 추려서** 묻고,
   나머지는 "기타"로 받는다. 바탕색만 바꾸고 싶다면 `brand.bg`로 덮을 수 있다(글자색은
   대비를 재서 자동으로 뒤집힌다).

6. **계정 표기** — `brand.showHandle` / `brand.handle` 또는 `brand.wordmark`

   **기본은 안 찍는 것이다.** 남의 계정 이름을 카드마다 새기는 건 그 사람이 원할 때만
   할 일이라, 예전처럼 표지 하단에 핸들을 자동으로 박지 않는다(2026-08-22).
   **반드시 물어본다** — "카드에 계정 이름을 넣을까요?"
   - "넣는다" → `showHandle: true` + 표기할 문자열을 받는다(핸들이든 브랜드명이든)
   - "안 넣는다"(기본) → `showHandle`을 아예 안 쓴다

   넣는다고 했는데 표기를 못 받았으면 렌더하지 않고 다시 묻는다 — 예전엔 둘 다 비면
   "AI 안하루"가 그대로 찍혀서 남의 브랜드명이 자기 카드로 나가는 사고가 났다.

   **판형 톤은 매번 반드시 묻는다 — 건너뛰지 않는다.**(2026-08-14: 어떤 세션은 묻고 어떤
   세션은 안 물어서 들쭉날쭉하다는 지적이 있었다. 강조색·테마를 이미 물었다고 이 질문이
   저절로 끝난 게 아니다 — 서로 다른 필드다.) 서로 독립인 두 결정이라 AskUserQuestion **한
   호출 안에 질문 두 개**로 나눠 묻는다(하나의 multiSelect로 묶지 않는다 — 아래 이유 참고):

   - **다크 판형** — `brand.surface`. "흰 배경(기본)" / "다크(카드 전체가 통짜 블랙)" 중 하나.
   - **종이질감** — `brand.texture`. "없음(기본, 순백)" / "옅게(보일락 말락)" / "진하게(눈에
     띄게)" 중 하나. **2026-08-14: 켜고 끄고 하나뿐이던 걸 강도 선택으로 넓혔다** — "선택"이라고
     해놓고 실제로는 이진값 하나였다는 지적이 맞았다. 파일이 커지고 인스타 압축에서 입자가
     뭉개져 지저분해 보일 수 있다는 걸 선택지 설명에 적어둔다(특히 "진하게").

   둘 다 **각각 안에서는 서로 배타적**이다(다크면서 동시에 라이트일 수 없고, 질감도 세 단계 중
   하나뿐이다) — 그래서 체크박스(multiSelect)가 아니라 각각 단일선택 질문으로 둔다. 두 질문을
   같이 물어도 되지만 한 질문으로 합치지 않는다: 합치면 "옅게"와 "진하게"를 동시에 고르는 게
   선택지 구조상 가능해져 버린다.

   바꿀 수 있는 건 여기까지다. **글자 크기·여백·폰트는 사용자가 못 바꾼다** —
   판형이 흔들리면 카드가 아마추어로 보이기 때문에 의도적으로 잠가둔 부분이다.
   글자 크기는 덱 전체를 보고 렌더러가 한 배율로 정한다(카드마다 다르면 넘길 때 제목이 튄다).
   더 바꾸고 싶다고 하면 `src/MediaCard.tsx`를 직접 고치는 방법을 안내한다(스킬이 대신 고치지 않는다).

### 1단계 완료 체크리스트 — 전부 확정돼야 2단계로 넘어간다

- [ ] 주제
- [ ] 소재 준비 상태 (있음 / 없음 / Unsplash로 찾기 — 화면형 주제면 Unsplash 항목 자체가 없는 게 정상)
- [ ] 내용 전달 방식
- [ ] 카드 수
- [ ] 무드 — `mood` (11종 중 하나, 기본 press)
- [ ] 계정 표기 — 넣을지 여부(`showHandle`). 넣는다면 표기할 문자열까지
- [ ] 강조색(`accent`) 또는 테마(`theme`) 중 하나
- [ ] 판형 톤 — 다크 여부·질감 강도 두 질문 다, 답이 둘 다 "기본값"이었어도 **실제로 물었다는
      사실**이 체크 대상이다("어차피 기본값이니 안 물어도 됨"은 여기서 성립하지 않는다)

하나라도 안 채워진 채로 2단계(소재 확인)로 넘어가지 않는다. 다시 채우는 방법은 §1을 처음부터
다시 도는 게 아니라, 안 채워진 항목만 AskUserQuestion으로 마저 묻는 것이다.

## 2. 소재 확인

**사용자를 폴더로 보내지 않는다.** 소재는 스킬이 가져온다 — 아래 순서로 한다.
예전엔 `<로컬 경로> 같은 경로를 주고 직접 넣으라고 했는데,
비개발자에게 이건 그 자체로 벽이고 "편하려고 받은 도구"가 미리캔버스보다 번거로워지는 지점이다.

1. **최근 파일에서 먼저 찾아본다** — 다운로드·바탕화면·비디오·사진 폴더에서 최근 1주일 안에
   생긴 mp4·png·jpg를 조용히 훑어(도구 호출로만, 과정은 안 보여준다) 후보를 목록으로 보여준다:
   ```bash
   # Windows 예 — 경로에 공백·한글이 있어도 되게 따옴표로 감싼다
   find "$USERPROFILE/Downloads" "$USERPROFILE/Desktop" "$USERPROFILE/Videos" "$USERPROFILE/Pictures" \
     -maxdepth 1 -mtime -7 \( -iname '*.mp4' -o -iname '*.png' -o -iname '*.jpg' -o -iname '*.jpeg' \) 2>/dev/null
   ```
   찾은 게 있으면 **파일명과 만든 시각을 AskUserQuestion 선택지로** 보여주고 고르게 한다.
   화면 녹화는 대개 방금 찍어서 여기 있다 — 이 한 단계로 대부분 끝난다.
2. **못 찾았으면 AskUserQuestion으로 묻는다**(플레인 텍스트로 "채팅에 적어주세요"라고 안내하고
   끝내지 않는다 — §1 첫머리 원칙과 같다). 예: "지금 파일을 여기 채팅창에 끌어다 놓을게요" /
   "화면 녹화부터 할게요"를 옵션으로 주고, **경로를 이미 아는 사람은 "기타"에 바로 붙여넣게
   한다**(탐색기에서 파일 우클릭 → "경로로 복사"). 파일을 드래그하는 것 자체는 어차피 다음
   채팅 턴에서 일어나지만, 그걸 기다리는 동안 "뭘 하면 되는지"는 위젯 하나로 끝나야 한다.
3. **경로를 받으면 스킬이 직접 복사한다.** 사용자는 어디로 가는지 알 필요가 없다:
   ```bash
   mkdir -p "<렌더러폴더>/public/clips/<주제slug>"
   cp "<사용자가 준 경로>" "<렌더러폴더>/public/clips/<주제slug>/"
   ```
   복사한 뒤 파일이 실제로 있는지 확인하고, **덱 JSON의 `clip`에는 `clips/<주제slug>/<파일명>`
   상대경로를 쓴다**(렌더러가 `public/` 기준으로 읽는다).

- 화면이 필요한데 아무 데도 없으면: **화면 녹화를 안내만 한다** — OS 기본 녹화 기능
  (Windows: Win+G, Mac: Cmd+Shift+5)으로 본인이 쓰는 도구·화면을 10초 이상 찍어달라고 요청.
  다 찍으면 1번으로 돌아가 다시 훑는다(방금 찍은 게 최근 파일로 잡힌다).
- 이미지(png/jpg)만 있어도 된다 — 렌더러가 자동으로 10초 켄번즈(천천히 확대)를 건다.

### Unsplash 무료 스톡 사진 찾기

실물 사진이 맞는 주제에서 사용자가 이걸 고르면:

1. **키를 조용히 찾는다** — 아래 순서로, 도구 호출로만 확인하고 과정은 안 보여준다(§0-A와 같은 원칙).
   찾는 곳이 여러 군데인 이유는 **플러그인 캐시 안에 둔 키는 재설치 때 통째로 날아가기** 때문이다.
   1. 환경변수 `$UNSPLASH_ACCESS_KEY`
   2. `~/.claude/haru-cardnews.env` ← **여기가 정식 자리다.** 플러그인을 다시 깔아도 안 지워진다
   3. 렌더러 폴더의 `.env` (직접 clone해서 개발하는 경우)

   - **키가 없으면 멈추지 않는다.** "사진 없이 텍스트 카드로 갈까요, 아니면 본인 사진을 쓰실까요?"로
     **그냥 이어간다.** 카드뉴스를 만들려고 온 사람을 API 키 발급 심부름부터 보내면 안 된다 —
     여기서 멈추는 순간 이 도구는 미리캔버스보다 느린 물건이 된다.
   - 사용자가 "그래도 스톡 사진을 쓰고 싶다"고 **먼저 말할 때만** 발급을 돕는다. 비개발자는
     "API 키 발급받으세요" 한 줄로는 못 움직인다 — 페이지를 직접 열어주고 클릭 단위로 안내한다.
     **계정은 대신 만들어주지 않는다** — 가입 자체는 항상 사용자 본인이 한다. (아래 문구·순서는
     2026-08-14에 실제 페이지를 직접 열어 확인한 것이다 — 화면이 바뀌었으면 눈에 보이는 대로
     사용자에게 안내한다.)

     1. 브라우저를 대신 열어준다(사용자가 주소를 찾을 필요가 없게):
        ```bash
        # Windows
        start https://unsplash.com/developers
        # Mac
        open https://unsplash.com/developers
        # Linux
        xdg-open https://unsplash.com/developers
        ```
     2. 순서를 한 번에 다 보여준다(질문 하나씩 끊지 않는다 — 어차피 전부 사용자가 그 페이지에서
        직접 하는 일이다):
        - 오른쪽 위 **"Register as a developer"** 클릭 (이미 계정 있으면 로그인만)
        - 이메일로 가입 — **카드 등록 없음, 시간당 1,000장 조회까지 무료**(페이지에 명시돼 있다)
        - 가입되면 "New Application" 버튼 클릭
        - 이용약관 체크박스 두 개 체크 → **Accept terms**
        - Application name·Description에 아무거나 한 줄씩 적어도 된다(예: `카드뉴스`,
          `personal card news`) → **Create application**
        - 그 페이지에 뜨는 긴 문자열이 **Access Key**다
     3. 키를 채팅에 붙여넣어 주면 스킬이 `~/.claude/haru-cardnews.env`에 대신 저장한다
        (한 번만 하면 다음부터는 안 묻는다). **저장한 키 값을 채팅에 다시 쓰지 않는다.**
        AskUserQuestion으로 "발급받으셨으면 여기에 붙여넣어 주세요" / "안 할래요, 텍스트
        카드로 갈게요" 를 옵션으로 주고, 키 자체는 **"기타"** 자유 입력 칸에 받는다.
2. **있으면** 주제에서 뽑은 영어 검색어 1~2개로 사진 3장을 조용히 받는다:
   ```bash
   curl -s -H "Authorization: Client-ID $UNSPLASH_ACCESS_KEY" \
     "https://api.unsplash.com/search/photos?query=<검색어>&per_page=3&orientation=portrait"
   ```
   응답의 `results[].urls.regular` 링크를 각각 받아서 저장한다(사용자는 이 경로를 알 필요 없다):
   ```bash
   curl -s -o "<렌더러폴더>/public/clips/<주제slug>/unsplash-1.jpg" "<regular 링크>"
   ```
3. **받은 3장을 Read 도구로 먼저 보여주고, 그 다음 AskUserQuestion으로 고르게 한다** — 사진을
   눈으로 보여준 뒤 "1번으로 할게요" / "2번으로 할게요" / "3번으로 할게요" / **기타(다른
   검색어로 다시 찾아주세요 — 뭘로 찾을지 적어주세요)** 로 묻는다. 마음에 드는 게 없으면
   "기타"에 적힌 새 검색어로 다시 받는다 — 억지로 고르게 하지 않는다.
4. **사용자가 고르면 Unsplash API 이용 규정에 따라 다운로드를 등록한다** — 고른 사진의
   `links.download_location` 링크로 GET 요청 한 번을 조용히 보낸다:
   ```bash
   curl -s -H "Authorization: Client-ID $UNSPLASH_ACCESS_KEY" "<download_location 링크>"
   ```
   (실제로 쓸 사진에 한해서만 보낸다 — 후보 3장 받을 때가 아니라 사용자가 고른 뒤 한 번.)
5. 고르지 않은 나머지는 지운다. **`card.label`에는 넣지 않는다** — 완성된 사진 위에 출처
   딱지를 박으면 카드가 지저분해 보인다는 피드백이 있었다(2026-08-13). 대신 응답의 `user.name`을
   기억해뒀다가 **§6 캡션 맨 끝에 한 줄로 모아 적는다**: `사진: Unsplash(작가명1, 작가명2 …)`.
   여러 장을 썼으면 한 줄에 다 모은다 — 카드마다 반복하지 않는다.

**판형은 소재가 정한다** — 사용자에게 "어떤 판형이 좋으세요?"라고 묻지 말고, 소재를 보고 정한 뒤
기획안에 적어서 승인받는다.

- **화면 녹화·스크린샷(16:9 UI)** → 기본 창 판형. 자료를 안 깎는 게 중요하다. 전면으로 깔면
  4:5에 맞추느라 좌우가 크게 잘려서 정작 봐야 할 UI가 날아간다.
- **사진·생성이미지(자료가 주인공)** → `"full": true` 전면 판형. 자료가 카드를 꽉 채우고
  하단 그라데이션 위에 흰 글자가 얹힌다.
  단, **자료가 조용해야 한다** — 자기 헤드라인이 큼직하게 박힌 이미지를 전면으로 깔면 그 글자와
  카드 제목이 서로 싸워서 둘 다 안 읽힌다. 그런 자료는 창 판형으로 간다.
- **영상은 10초 이상이어야 한다.** 소재가 있다고 한 사용자에게도 이걸 먼저 알려준다 —
  기획·승인까지 다 끝낸 뒤 렌더에서 막히면 그 과정이 통째로 헛일이 된다.

### 2단계 완료 체크리스트 — 전부 확정돼야 3단계로 넘어간다

- [ ] 카드마다 쓸 소재(clip 경로) 또는 "소재 없음(텍스트 카드)"이 확정됨
- [ ] 소재가 실제로 렌더러 폴더 안(`public/clips/<주제slug>/`)에 있음(경로만 받고 복사 안 한
      채로 넘어가지 않는다)
- [ ] 영상 소재는 10초 이상임을 확인함(또는 사용자에게 미리 알림)
- [ ] 카드마다 판형(기본 창 / 전면 / 비교 / 단계)이 정해짐

## 3. 기획안 작성

### 카드 유형부터 고른다 (2026-08-13 신설)

모든 카드가 "사진/영상 + 제목 + 본문"일 필요는 없다. §1에서 고른 주제 카테고리에 맞춰
정보 카드 몇 장을 아래 전용 판형으로 바꿔 쓴다 — 억지로 사진 위에 글자만 얹는 것보다
내용이 훨씬 잘 산다. 판형은 카드마다 섞어 써도 된다(표지는 훅, 중간 2장은 비교/단계,
마지막은 CTA — 이런 식).

- **비교·선택 가이드 주제** → 핵심 비교 지점을 `card.compare`(2칸 대비, A vs B)로 만든다.
  "예전엔 / 이제는", "이거 / 저거" 처럼 대비가 분명할 때만 쓴다 — 대비가 약하면 그냥
  정보 카드가 낫다.
- **방법 안내 주제** → 순서가 있는 절차는 `card.steps`(번호 목록, 3~5개 권장)로 만든다.
  **한 항목은 15자 안쪽으로 짧게 쓴다.** 렌더러가 한 항목을 한 줄에 앉히려고 글자를
  줄이기 때문에, 20자를 넘기면 카드 전체 글자가 작아져 피드에서 안 읽힌다.
  "지시가 반복된다 싶으면 그 문장을 적어둔다"(20자) → "반복되는 지시를 적어둔다"(12자).
  "1단계 카드, 2단계 카드…"로 슬라이드를 쪼개지 않는다 — 한 카드 안에 목록으로 모은다.
- **도구·소프트웨어 소개 주제** → 화면 녹화가 주인공이니 기본 창 판형을 쓴다. 비교·단계는
  화면이 없는 카드에만 보조로 섞는다(예: 마지막 요약 카드 하나만 `steps`로).
- **소식·후기, 실물 사진 주제** → 사진이 있으면 `card.full` 전면 판형(§2), 없으면 기본
  정보 카드.

**`card.badge`는 아껴 쓴다.** 카드 전부에 붙이면 장식이 아니라 잡음이 된다 — 유형이 확 바뀌는
카드(비교·단계·속보성 소식)에서 1~2장만, 그 카드의 역할을 한두 단어로 짚을 때만 쓴다
("COMPARE", "HOW TO", "TREND" 같은 식). 모든 카드에 습관적으로 붙이지 않는다.

카드별로 아래를 **표로** 만들어 사용자에게 보여준다(아직 JSON 아님, 사람이 읽는 초안).

| # | 유형 | 제목 | 본문 | 클립 |
|---|---|---|---|---|
| 1 | 훅 | ... | | ... |
| 2 | 정보 | ... | ... | ... |
| N | CTA | ... | ... | (없음) |

### 카피 규칙 (건너뛰지 말 것)

- **인터뷰에서 못 받은 사실·수치는 빈칸으로 남기고 다시 묻는다.** §0/§1의 "조사 안 함" 원칙은
  선언이 아니라 지금 이 순간 지켜야 하는 것이다 — 인터뷰가 끝났다고 이 단계에서 알아서
  채우면 원칙이 있으나 마나다.
- **헤드라인은 명사로 끝난다.** `~입니다/~해요/~습니다` 금지 — "손안의 노래 1,000곡." 식으로 끊는다.
  종결어미는 본문 몫이다.
- **`*단어*`로 감싸면 액센트 색+굵기 강조가 된다.** 핵심 숫자·단어 하나에만 쓴다(문장 전체에 걸지 않는다).
  예: `"AI 영상 한 편 뽑는 값\n*4,800원*부터."`
- **본문은 한 문장 = 한 줄**(배열 원소가 줄바꿈), 0~3줄, 40자 이내. 종결어미(`~입니다/~죠/~예요/~거든요`)를
  섞는다 — 한 어미로 카드 전체를 도배하지 않는다.
- **1번 카드(훅)는 4킬러 감사를 통과해야 한다.**
  - DELAY: 주제가 첫 어절에 오는가
  - CONFUSION: 한 번에 이해되는가
  - IRRELEVANCE: "[회사/도구]가 [기능]을 냈다" 식 보도문이 아니라, 읽는 사람이 느끼는 불편을 건드리는가
  - DISINTEREST: 통념(A) 대 실제(B)의 대비가 있는가 — 대비가 궁금증을 만든다
  - 걸리는 게 있으면 다시 쓴다. 특히 잘 먹히는 구조: **"[결과가 안 좋은 건] 능력 문제가 아니라
    [이름/순서/설정]을 몰랐을 뿐"** — 남 탓·회사 탓으로 흐르면 반려, 탓하는 대상은 항상 "몰랐다는 사실" 하나다.
- **과장 금지.** "역대급", "이제 ~는 끝났다", 근거 없는 "최강" 금지. 숫자는 최대치를 평균처럼 쓰지 않는다.
- **화면이 보여주는 걸 텍스트가 또 말하지 않는다.** 카드 텍스트는 화면이 안 보여주는 맥락·수치·의미만 담는다.
- **마지막 장은 CTA 전용.** 클립 없이 텍스트만(정지 이미지로 렌더됨). 매번 다른 유형으로:
  프로필 링크 유도 / 저장 유도 / 의견 질문 / 공유 유도 / 다음 예고 중 소재에 맞는 걸 고른다.
  **"댓글 남기면 DM" 방식은 쓰지 않는다** — 플랫폼이 스팸으로 판정해 계정이 정지될 수 있다.
- **팔로워 시점 최종 점검**: 완성본을 1번부터 끝까지 읽고 "내가 이 계정 팔로워라면 뭘 얻었나"에
  한 문장으로 답이 안 나오면 카드가 아니라 주제 자체를 다시 잡는다.

### 3단계 완료 체크리스트 — 전부 통과해야 4단계(승인)로 넘어간다

- [ ] 표 안의 모든 문장이 §0/§1에서 사용자가 준 내용에서 나왔다(카드 문구 작성 중 새로 지어낸
      사실·수치 없음)
- [ ] 헤드라인이 전부 명사로 끝남
- [ ] 1번 카드가 4킬러 감사를 통과함
- [ ] 마지막 장이 CTA이고 "댓글 남기면 DM" 방식이 아님
- [ ] 팔로워 시점 점검 문장이 나옴

## 4. 승인 게이트

기획안 표를 보여주고 확인받는다. "이 카드 문구 바꿔줘", "3번 빼줘" 같은 요청은 대화로 계속 반영한다.
**사용자가 명시적으로 괜찮다고 할 때까지 다음 단계로 안 넘어간다.**

## 5. 렌더

승인되면 덱 JSON을 `<렌더러폴더>/public/mediadecks/<주제slug>.json`에 스키마대로 쓴다(스키마 상세는
저장소 루트 `README.md` "덱 스키마" 절 참고 — 이 파일과 항상 같이 다닌다).

**같은 이름의 덱이 이미 있으면 먼저 물어본다** — 그냥 쓰면 예전 카드뉴스가 덮어써진다.
이어서 고치는 거면 그대로 쓰고, 새로 만드는 거면 slug 뒤에 `-2`를 붙인다. 재사용할 때
카드 수가 줄었다면 `out/<주제slug>/`에 남은 뒷번호 파일을 지운다 — 안 지우면 사용자가
캐러셀에 옛 카드를 섞어 올리게 된다.

그 다음 실행한다. **반드시 렌더러 폴더에서 실행한다** — 스크립트가 현재 폴더 기준으로
`public/`과 `out/`을 찾기 때문에, 다른 폴더에서 부르면 "덱 파일이 없습니다"가 나거나
결과물이 엉뚱한 곳에 생긴다:

```bash
cd "<렌더러폴더>" && node scripts/mediacards.mjs <주제slug>
```

렌더 스크립트가 알아서 클립 길이를 재고 카드 길이를 맞춘다 — 이 스킬이 계산하지 않는다.

**시작 전에 대기 시간을 알려준다** — 카드 한 장에 30초 안팎이므로 "카드 N장이면 2~3분쯤
걸립니다. 끝나면 알려드릴게요." 정도로 말한다(느린 컴퓨터면 더 걸릴 수 있다).
아무 말 없이 몇 분씩 멈춰 있으면 사용자는 멈춘 줄 알고 창을 닫는다.

에러가 나면 그대로 사용자에게 보여준다. **중간에 실패했으면 처음부터 다시 하지 않는다** —
앞 카드는 이미 `out/`에 나와 있으므로, 실패한 번호부터만 `--only 3,4,5`로 이어서 렌더한다.

## 6. 캡션

렌더가 끝나면 인스타 캡션·해시태그를 별도 텍스트로 써서 `out/<주제slug>/캡션.txt`에 저장한다.
캡션도 §3의 카피 규칙(과장 금지, 팔로워 시점)을 따른다. 5개 이하 해시태그, 이모지 금지.
Unsplash 사진을 썼으면 맨 끝에 출처 한 줄을 더한다(§2 참고).

**캡션도 §0의 "조사 안 함" 원칙을 그대로 따른다.** "이번 시즌 런웨이에서 반복된 건 ~였다"처럼
사용자가 안 준 리서치·통계·트렌드 근거를 캡션에서 지어내지 않는다 — 카드 문구는 §3에서
걸러졌어도 캡션은 별도로 쓰는 글이라 여기서 새로 지어내면 소용없다. 카드에 이미 쓴 내용을
정리·요약하는 선을 넘지 않는다. 넘는 순간 "성의 없는 뻔한 광고 카피"처럼 읽힌다 — 그 정체가
바로 근거 없이 지어낸 문장이기 때문이다.

마지막에 `out/<주제slug>/` 안의 파일 목록과 캡션 내용을 사용자에게 보여주고,
**"고치고 싶은 카드 있으면 말씀해 주세요"라고 안내하며 마친다**(§7이 있으니 여기서 끝이 아니다).

## 7. 렌더 후 수정 — 말로 고친다

영상이 나온 뒤에도 사용자는 얼마든지 고칠 수 있다. **처음부터 다시 하지 않는다.**

> "2번 카드 제목이 좀 약한데 바꿔줘"
> "3번 본문 두 번째 줄만 빼줘"
> "전체 톤을 neon으로 바꿔줘"

절차:

1. `public/mediadecks/<주제slug>.json`을 읽어 현재 상태를 확인한다
2. 요청대로 해당 카드만 고친다(§3 카피 규칙은 수정본에도 그대로 적용한다 — 고친 문장이 규칙을
   어기면 그게 다음 반려 사유가 된다)
3. **바뀐 카드 번호만** 골라 재렌더한다:

```bash
cd "<렌더러폴더>" && node scripts/mediacards.mjs <주제slug> --only 2
```

여러 장이면 쉼표로: `--only 2,3`

4. 전체를 다시 돌리지 않는다 — 카드 한 장에 30초 안팎이 걸리므로 안 바뀐 카드까지 재렌더하면
   사용자 시간을 그만큼 버린다.

**무드(`brand.mood`)나 바탕색(`brand.bg`)을 바꾼 경우는 예외** — 모든 카드에 영향을 주므로
`--only` 없이 전체를 다시 렌더한다.
